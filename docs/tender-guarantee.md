# 有效投标、保证金期限与国家节假日日历

适用版本：v5.8.27。投标保证金以实际交付情况为准，不按报名名单自动推定。

## 日常使用

1. 在开标或评审面板的“实际参与与有效投标”中逐家核对：未参加、未提交文件、文件未接收、已提交并接收；同时确认投标有效性、实际缴纳情况和金额。无效、未参加及文件未接收填写原因。
2. 确认已核对的名单。更新版本后仍未完成结果公告的项目，新增或修改中标/成交结果只能选择该采购包已确认的有效投标供应商。报名和参与资料变动后须重新确认。联合体仍按一个投标主体识别，成员变化也会使名单待复核。
3. 在保证金面板新增规则：对象、采购包、实际起算阶段或手动日期、期限天数、自然日/工作日、可选截止时分与提前提醒。规则默认关闭；确认采购文件和实际事项后再启用。“签订委托协议”不等于采购合同签订。
4. 实际缴纳的供应商选择“按规则处理”后，指定阶段完成并有实际完成日期时生成截止日。结果未确认、实际日期缺失、年度调休数据未确认等情况显示待核实，不估算截止日。
5. 退还后登记累计已退金额；部分退还只减少余额，全额退还停止到期邮件和日历待办。无效投标但已经缴纳的供应商仍在列表中；按规则退还、待核实或暂缓处理由经办人确认。暂缓须填写原因及复核日期，仍显示原期限和逾期状态。

项目流程设置可保存各采购方式的新项目默认规则，只在以后创建的项目中取快照，不追溯修改已有项目。项目中仍可单独调整。新创建项目的结果阶段自动完成也必须通过有效投标和结果核对。

## 保证金更正与记录

实际退款填写“累计已退金额”，不要把实际缴纳金额改成零。误录缴款更正需要单独勾选确认并填写凭据依据。报名主体、联合体成员或采购包变化后，原缴款快照保留并标记需核实；供应商报名或采购包被删除也不抹除未退余额。每次修改需填写原因，版本与历史记录保存在扩展表中。

实际起算阶段改期或撤销、规则变动或节假日安排变化时，已生成期限保留原值，并显示拟调整期限；经办人复核并填写依据后才采用新期限。日历显示全天的日期型期限，内部以当天结束判断逾期；填写时分的期限按所填时分判断。从实际起算日的次日开始计数。

## 日历和邮件

2026年内置国家放假、调休安排，来源为[国务院办公厅通知](https://www.beijing.gov.cn/zhengce/zhengcefagui/202511/t20251104_4258873.html)。放假用淡暖色和“休”标记，周末补班用淡蓝色和“班”，普通周末使用轻微灰色。该数据同时用于保证金工作日期限：全部放假日排除，调休补班计入。自然日期限连续计算。

日历“安排与更新”以及邮件设置中可查看年度数据、官方来源，并检查更新。后台每周检查本仓库经核验的年度数据文件；离线或获取失败保留原安排。未覆盖年度显示未确认，不据普通周末推算。更新只更新年度数据，不静默移动已生成截止日。

在收件组选择“保证金退还”“保证金待核实”及所需内容字段，再预览或测试。保证金提醒沿用主开关、发送时分和星期；可选择改为仅国家安排的工作日发送，包含补班。工作日数据未确认时暂停这种发送。程序关闭不能发邮件，启动后检查当前有效事项，不补发大量过期历史通知。同一项目、提醒类型、收件人每天汇总一次；全额退还后不发送。发送失败记录可查看并重新排队，状态不确定的发送不会静默重复，手动重试前须核实收件情况。邮件不包含银行账号等字段。

项目归档、进度100%、流标或终止不会自动抹除已缴且未退的保证金。期限和退还处理是管理记录，不自动作出无效投标不退保证金的判断；暂缓也不改变适用的原期限。

## 升级保护与验证边界

首次升级记录规则版本和已完成阶段。旧项目已完成的结果公告、整项目完成状态及既有供应商结果保留，不回填有效性、不重算、不删除。未完成公告的旧项目既有结果仍保存，后续新增、修改和完成公告前核对名单。旧项目不自动生成保证金任务或发送历史提醒。

开发使用隔离数据库、模拟供应商和模拟SMTP；真实成品验证包括新项目有效名单、无效已缴款、两类期限、国家日历、明暗主题/窄屏、重启以及v5.8.26升级后已完成项目数据一致性。自动完成报名逾期个案仍按用户要求暂缓，本版本新增结果核对保护不代表已定位该个案。历史核心仍是编译运行时。真实桌面验收、收件客户端实际渲染和实际运营电脑数据不属于隔离验证范围。

验证记录：前端322项通过；Python735项运行（711通过、24按环境跳过）；最终兼容成品12组HTTP/浏览器/历史升级检查通过，公开首次运行另行校验。模拟SMTP包含主开关、每项目每日汇总、重复收件人合并、部分退款后更新待发内容、发送失败延迟重试及退款后取消待发。未发送真实邮件。
