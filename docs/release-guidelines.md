# 发布页写法

发布页使用正式更新日志的写法，读者能快速查看版本变化和找到下载文件。结构参考 [DeepSeek Harness 发布说明](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-alpha.1)。

- 发布标题只写版本号，例如 `v5.8.19`。具体改动放在正文，保留原标签和历史版本。
- 从项目维护者角度直接描述变更，不强行使用第一人称；避免“这次我”“我用隔离数据验证了”等工作汇报叙述。
- 按实际变更选择“✨ 新增功能”“🐛 问题修复”“🎨 体验优化”“⚠️ 其他说明”分类，没有内容的分类不出现。
- 每条写明变化、触发条件或影响，避免空泛的“主要修复了几个问题”“日常操作保持不变”。不虚构新增功能、贡献者或验证结果。
- 使用步骤、详细测试结果及源码边界通过文档链接提供；正文只保留本版相关说明和简短的 AI 编制、许可声明。可提供相邻标签的完整更新记录链接。
- 附件列表使用中文显示名，分别标明项目系统、自由运用版授权工具、绑定磁盘版授权工具、完整包和校验文件。
- 中文名称通过附件的显示标签设置；实际文件名、下载地址及校验内容保留兼容。完整包内的成品仍使用正式中文文件名。
- `Source code (zip)` 和 `Source code (tar.gz)` 是 GitHub 自动生成的源码入口，保留平台默认名称。
- 本地先保存说明、映射与校验记录，再同步 GitHub。发布页整理不替换已有 EXE，不改许可证或运行数据。
- 保留 AI 编制声明、MIT 许可证、首次使用步骤及历史核心源码边界。

各版本正文保存在 `docs/releases/notes/`，与发布标签同名。更新正文后，先准备计划：

```powershell
py -3.12 tools/release_presentation.py --tag v5.8.19-public --report release-plan.json
```

检查计划中的标题、正文和中文显示名，再应用并验证：

```powershell
py -3.12 tools/release_presentation.py --report release-plan.json --apply
```

不传 `--tag` 时处理已有正式发布。工具核对发布状态及原始内容，防止覆盖准备计划之后的其他修改；只更新正文、标题和显示标签。
