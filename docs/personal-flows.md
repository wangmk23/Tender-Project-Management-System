# 专属流程升级与配置页

专属兼容EXE适用于已有授权部署。使用电脑原有的采购方式流程作为来源，直接更新同名采购方式的默认模板；不把开发电脑的流程或真实数据打入程序。通用公开版保留按制度管理，并不会自动启用专属迁移。

## 实际使用

退出实际使用电脑的旧程序，保留完整原数据目录及其备份，将专属兼容EXE放在原程序的数据目录后手动启动。不要使用公开自建密钥版替换原授权程序。开发交付不会替用户切换或重启原程序。

第一次启动专属版时，读取当地已经保存的流程配置：旧配置尚未迁移到采购目录时，先沿用已有迁移流程读取；已经迁移的，直接使用原目录。只更新默认模板，历史项目的阶段名称、顺序、完成时间、供应商结果与采购方式快照不参与本操作。

在“系统设置 → 项目流程”中，左侧选择采购方式，右侧查看阶段；“编辑流程”继续打开居中弹窗。专属模式显示“我的采购流程”，原保存方式可以直接新建项目，不必处理“待分配”。历史引用保留在后台，同名参考条目不再重复出现在专属选择列表。

## 匹配与保护

- 优先识别旧版保留的配置、手工创建的方式及有流程编辑记录的方式。同名来源流程相同才自动选定；有不同的自定义流程时保留来源并提示核对，不按最后时间、字数或制度猜测。
- 阶段名称、顺序、图标、业务模块和阶段属性整体沿用保存的配置，不从现有项目的完成进度反推默认模板。
- 覆盖同名目标前检查保证金默认起算阶段。锚点不兼容时保留该项及其规则并提示，不擅自删除保证金设置。
- 首次迁移在SQLite事务内完成，原模板存入本地`personal_flow_profiles.before_json`，并追加配置审计。该表用于维护核对和恢复，不提供自动还原按钮。
- 每个数据库只激活一次。重启与后续升级不会重新套用初始流程，管理员后续编辑会保留。专属模式保存在数据库中；切换EXE文件不等于恢复配置。
- 旧方式标识和历史引用不删除，不修改真实数据文件、许可文件或邮箱设置。保留的旧条目仍可用于解释历史项目。
- 原本没有采购制度的方式继续不宣称法律归属，专属模式仅允许其作为保存过的个人默认方式使用；数量仍为管理预警，不直接作为法定门槛。

## 构建

源模块`personal_flows.py`默认关闭。只有兼容升级构建显式传入`--personal-flows`，编译器才将启用常量编入EXE。运行时环境变量不能激活它；公开构建拒绝携带启用标记的构建环境。

不需要把实际电脑的数据库、许可证、邮箱密码或完整配置传回开发电脑，也不将用户配置发布到GitHub。
