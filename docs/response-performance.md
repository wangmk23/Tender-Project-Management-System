# 起始保证金与响应优化

适用版本：v5.8.29。

## 项目开始时设置

新建项目窗口直接填写“文件要求的保证金金额（元）”，无需先进入开标或退还阶段。分包可填写自己的保证金金额，留空沿用整体项目金额。勾选“无需投标保证金”后金额输入禁用，创建请求不携带该金额。

文件要求金额与项目、采购包一起保存；金额无效时阻止创建。此设置不会自动登记供应商实缴、退款或有效投标。已有项目在“信息”页点击“设置金额”，金额调整不改写已登记的实缴和已退记录。

## 已确认的响应问题

日历保证金入口原来先等完整项目导航完成，再读取保证金台账。新版立即显示读取反馈，一份项目详情返回后直接使用其中的台账，不再重复请求。参与核对、缴款和退款表单共用已加载台账；并发缺失读取合并成一个请求。保存仍携带台账修订号，冲突时阻止覆盖。

关闭窗口、换项目或换页面后，迟到响应不重新打开面板；加载失败提供重新加载。设置金额时不再打开先前已经关闭的阶段。

后端原先逐个完成阶段查询数据表结构和模块。现改为一次读取阶段元数据，并使用当前事务连接。保证金日历及邮件只加载有保证金记录的项目，关联数据批量读取；无台账时不逐项目空查，日历计算也不重复统计邮件队列。

## 验证与边界

相同的隔离测试中，120个项目、12个有保证金记录：保证金日历扩展查询由661条降到98条，单个有记录项目由45条降到9条。该计数针对保证金扩展，不代表整个日历接口的全部查询。

实际成品浏览器注入350毫秒请求延迟，读取反馈约4毫秒出现，打开处理面板只发出1次项目详情请求、0次重复台账请求。此结果是本机无头测试，不能推断实际局域网或使用电脑的最终耗时；不承诺所有操作按相同比例提速。

另用同一份30项目、9个有缴款记录的隔离数据库，按旧版、新版、旧版、新版交替运行，每接口每轮7次采样。日历中位耗时约265/269毫秒降至247/253毫秒；单次详情约238/242与248/244毫秒，列表约310/298与306/305毫秒，后两项没有稳定提速证据。后台系统负载未完全受控，结果仅用于本机对照；改进不等于所有接口都更快。

前端331项通过；Python744项运行（720通过、24项环境跳过）。兼容成品15组隔离HTTP/界面检查覆盖新建与分包金额、无效金额回滚、无需保证金、已有缴退款、日历操作及历史完成数据；公开版15组首次运行检查通过。未发送真实邮件，未替换或重启测试运行目录程序。
