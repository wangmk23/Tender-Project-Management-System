# PDF 阅读与流程更正验证方案

范围：现有预览增加书签、翻页、搜索、打印；改善桌面与外链网页视频加载；更正项目采购方式时同步项目流程。保持原有授权、数据加密、附件、四主题和业务密度。

1. 保留现有附件认证，使用固定哈希的官方 PDF.js 完整离线阅读器。父弹窗负责下载、关闭和生命周期，阅读器负责目录、搜索、分页和打印。关闭脚本、编辑、文件导入与自动打印；仅用户主动打印。扫描件明确能力边界。
2. 测量旧版实际 EXE 的视频准备、控件挂载和首帧，分别保存冷/热、本机/模拟网络、正反执行顺序。仅对证据支持的前端串行等待和轮询延迟优化；不削弱解密认证，不把受控浏览器覆盖结果当作新版成品结果。
3. 显式采购方式 ID 变化时，在同一事务应用目标流程和采购方式快照。复用共同及曾移除的阶段 ID；有完成记录或资料依赖的冲突明确拒绝。普通同方式保存和全局模板变更不自动覆盖项目自定义流程。
4. 执行回归、独立审查，再构建新版本公开/兼容候选。针对固定成品 SHA 验收 PDF、媒体和采购方式往返；记录原件校验、版本、基线及环境。
5. 本地交付和证据完成后更新入口与交接；未验原生桌面、真手机、物理打印明确列出，不自动重启现有运行程序。

验证：有针对性的回归先红后绿；全部前端、Python 检查；269 页 PDF 控制画布预算；真实 EXE 上传加密附件、书签、内链、文字搜索、用户打印准备、关闭/切换；视频首帧与内存；采购方式 A→B→A、资料冲突拒绝、事务回滚。
