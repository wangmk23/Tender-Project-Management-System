# 本地项目文件夹管理（开发分支 V1）

此功能与系统既有「附件」业务独立。项目资料保留在 Windows 主机及用户已配置的磁盘/共享目录，不同步或上传到管理系统。

## 操作

进入项目详情 → **本地文件**：

1. 使用系统主机本机登录的管理员账号，选择「关联现有文件夹」，填写服务器端可读取的绝对目录（如 `D:\\招标项目\\GDHD-2026-068_安保`）。
2. 或选择「创建标准文件夹」，填写已存在的父目录。系统使用项目编号及名称生成新目录，并在其下创建九个分类子目录。
3. 点击「扫描目录」可读取有限数量的文件元数据（文件名、所在相对子目录、大小和修改时间），并检查标准子目录是否存在。
4. 「打开文件夹（主机）」会在运行系统的 Windows 主机上执行 Explorer 打开操作，不会打开在远程同事电脑上。

## 安全与边界

- 不会自动删除、移动、重命名或覆盖任何项目文件；取消关联只删除映射。
- 每个项目拥有独立关联，仅允许一个项目目录绑定一个项目编号。
- 修改目录和本机打开操作均需要 **主机本机请求、管理员会话、有效 CSRF**。
- 远程浏览器可以读取本项目已关联目录的有限元数据，但不能操作主机文件资源管理器。
- 扫描深度至多四层，最多处理 1500 个条目、显示 100 个文件样本。符号链接与 Windows junction 跳过。
- 映射存储在系统 `DATA_DIR/local_project_folders.json`，写入采用临时文件和原子替换；读取发现索引损坏则拒绝覆盖。生产备份方案应包含此文件。
- 若项目被系统删除，当前版本不自动清除磁盘文件或此映射残留，便于人工核对追溯；重复关联可能需要后续维护管理接口处理。
- 本版本**不提供**远程客户端「打开自己的资源管理器」、文件全文搜索、自动资料分类、文件预览或批量迁移。
- 项目编号或名称在操作系统中不适合做目录名时会按 Windows 保留字符规则清理。
- 标准目录检查只校验文件夹存在，不认定招标归档资料齐备或合规。

## 开发与构建

后端入口 `src/backend_patches/local_project_folders.py`，通过 `desktop_app_replacements.main()` 注册；由 `tools/compile_module_patches.py` 集成到 PYZ。前端入口 `source/frontend/26-local-project-files.js`，通过 manifest 拼装，项目工作区模板增加标签。

执行：

```powershell
npm ci
node tools/build_frontend.js --check
py -3.12 -m unittest tests.test_local_project_folders
```

构建并验证 Windows 程序请遵循 `docs/build.md`，不得直接替换含生产数据的 EXE。还需要在 Windows 主机、局域网另一台电脑及 Tailscale 访问条件下验收权限和路径行为。

## 验收要点

- 原有项目详情、附件上传、修改及删除操作不受影响。
- 本机管理员能关联、创建新目录、扫描、打开主机 Explorer 和取消关联。
- 本机普通账号与远端管理员均不能修改关联、创建目录或打开主机 Explorer。
- 所有写接口必须校验 CSRF；路径穿越、设备命名空间、目录链接被拒绝。
- 已存在的同名目录不能覆盖；映射索引损坏时不自动重置。
- 既有业务目录及所有原有文件的内容和修改时间不应被改变。
- 系统恢复备份后应确认映射文件与项目数据一致。
