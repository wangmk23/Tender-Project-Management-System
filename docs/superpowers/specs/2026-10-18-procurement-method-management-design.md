# 采购方式、供应商数量与流程模板管理设计

日期：2026-10-18。基础版本：v5.8.36，提交 `5d814efe8b654825344145eb4db6e3ea3e3b3797`。

状态：设计供审阅，尚未修改产品代码、升级数据库或执行功能验收。原运行程序及业务资料保持原状。

## 目标与边界

将现有固定八种采购方式扩展为管理员可维护的目录，按适用采购制度管理，联动供应商数量规则和独立流程模板。各入口使用同一份目录。新项目采用创建时的配置快照，修改全局配置不改写已有项目；历史已完成结果不变。

本次按用户提供的管理分类实现，不新增或推断法定数量、法定期限、例外资格。数量均为管理员配置的业务检查值。适用制度与已有期限助手明确对接，但不根据采购方式名称自动判断法律适用或启用法定期限计算。

## 方案选择

推荐在现有 SQLite 中增加采购方式目录和项目绑定快照，目录中的数量规则与模板一次事务保存。这样项目创建与“被引用不可删除”可以在同一数据库事务内校验，避免文件设置与数据库之间发生竞争。

备选一：继续全部保存在设置 JSON。改动较小，但删除引用检查与项目创建跨存储，需额外解决一致性。备选二：建设独立制度和模板中心。能力更广，但增加本次不需要的界面和维护成本。本次不采用。

## 管理界面

沿用“系统设置 → 项目流程”，上部新增“采购方式”管理区，下部显示当前方式的“数量规则”和“默认流程”。删除原来重复的八方式数量输入卡片，避免两处配置。

1. 制度筛选：全部、政府采购、依法必须招标的工程建设项目、企业及国有企业自主采购、集体经济组织采购、其他采购。迁移记录可临时显示“制度待确认”，这只是迁移状态，不是第六类制度。
2. 方式列表：名称、制度、启用状态、默认数量或“不固定”、流程来源、项目引用数；提供新增、编辑、停用/启用、上移/下移和删除。
3. 新增/编辑使用已有居中弹窗。字段分为基本资料、数量规则、默认流程三组，保留取消、保存、字段错误和未保存提示。删除被引用记录时明确显示引用数量及“可停用”操作。
4. 列表按全局顺序保存；制度筛选只是过滤。上下移动调整当前可见相邻项的相对位置，不打乱其他制度的顺序。新建项目先选制度，再选该制度的启用方式，显示数量与流程摘要。
5. 名称在同一制度内不得重复；不同制度允许同名，由制度与稳定标识区分。历史项目显示创建时名称，必要时旁注当前名称与停用状态。
6. 保留四主题、字体、业务密度和自定义彩色 SVG。使用现有按钮、弹窗、输入组件与主题变量；数字手动输入，不加步进箭头。手机单列布局、键盘上下移动、焦点回到触发按钮、禁用状态说明与行内错误均须验证。
7. 依据本地 UI UX Pro Max 参考的字段分组、明确错误、焦点管理、点击反馈与性能规则，以及 Taste Redesign 的现有技术栈、状态完整性和局部改进规则，不迁移框架或重做全站风格。

## 配置与持久化

采购方式使用服务端生成且不可编辑的稳定标识，不以可变名称作关联键。

目录记录包含：标识、名称、制度、备注、启用状态、排序、版本、内置语义类型（旧方式迁移用）、数量规则、例外情形列表、独立模板或使用通用模板、创建/更新时间。

- 数量规则：`fixed` 时为1至99的整数；`unfixed` 时数量为 null，不用0伪装无要求。
- 例外情形：标题、适用说明、替代数量模式/数量及是否启用。不执行用户填写的表达式，不自动判断法律例外成立。
- 流程：独立阶段数组，或明确的“使用通用默认流程”。通用模板是独立配置，不能将列表第一种采购方式当成通用模板。
- 引用计数由数据库统计，涵盖项目和采购包重新采购使用的方式；删除在写事务内重新检查，不能只依赖页面计数。
- 配置保存使用事务与版本冲突检查；多人同时保存过期版本返回冲突并保留本地未保存输入，提示重新加载。
- 新增扩展表，不替换历史核心。配置写入成功后才返回成功并刷新缓存；失败完整回滚。重启及数据库备份/恢复均包含这些表。
- 保留现有管理员校验与 HTTP/CSRF 防护；普通用户可读取业务所需目录但不能修改。项目调整沿用项目编辑权限，不额外开放管理权限。

目录管理接口集中提供列表、创建、更新、重排、删除和通用模板读写；启用状态通过更新处理。项目 API 增加采购方式标识及制度/规则快照，保留现有 `method` 文本字段作为兼容显示快照。数据库中的新表是唯一权威来源，不再维护第二份可写 JSON 配置。

旧设置接口中相关键只保留受控兼容适配：可唯一映射的旧方式请求转换到目录事务，同名不明确或使用旧批量同步请求时返回明确错误。返回旧格式仅用于兼容，页面不出现双重保存入口。

## 历史迁移与停用

1. 首次升级在可回滚事务内导入旧八种方式、管理员已保存的数量和模板；不覆盖为出厂值。无历史配置时采用旧程序的业务默认值，并标注来源为“旧版默认配置”，不称为法律要求。
2. 旧配置没有制度信息时标为待确认，不根据“公开招标”等名称猜测。管理员确认制度后才用于新建项目；旧项目继续打开、编辑资料和推进。
3. 建立扩展表中的历史引用绑定与当前规则基线，不更新原项目 `method`、阶段、完成日期、有效投标名单、中标结果或保证金记录。历史流程按实际阶段读取，不能用新模板补齐成新流程。
4. 迁移重复运行不重复创建、不重置后来配置。发现不合法旧值时保留原文件，给出修复提示，不静默截断或覆盖。
5. 停用后从新建/改选/重新采购候选中移除；已引用项目保留显示和使用。编辑旧项目其他字段时不因原方式停用而拒绝保存。
6. 从未引用的方式可以确认后删除；存在引用只能停用。新增项目与删除方式并发时，由同一数据库事务保证不会产生失效引用。

## 数量不足处理

数量检查按“项目或采购包快照 → 本项目明确选择的例外/覆盖”求值。全局后续修改只影响新项目；已有项目采用新规则须主动预览并确认。

界面统一用“配置最低数量”“数量不足，待人工处理”，不再使用会暗示法律结论的“法定最低数量”“已自动流标”。所有提醒及邮件同步更改文案和状态。

| 场景 | 行为 |
| --- | --- |
| 不固定最低数量 | 不做数量差额警告，不显示达标；仍显示已登记数量及“不固定最低数量” |
| 固定数量且达到 | 显示数量检查满足；不等同于资格合格或流程合法 |
| 固定数量且不足 | 警告并提供“继续办理，填写说明”或“人工标记流标/终止”；不自动改变业务结果 |
| 未核对参与/有效性 | 显示待核对，不能把待确认当成0家或已经有效 |
| 选择例外情形 | 显示其适用说明、原规则和替代规则，人工选择并填写本项目说明后生效，记录操作者 |

报名模块统计报名记录；开标/文件接收模块统计实际提交并接收文件的供应商；评审/结果模块统计已确认有效投标的供应商。沿用已存在的参与、文件接收和有效性资料，不新增重复名单。未参加、未交文件、文件拒收不算已接收或有效投标。

预警本身不拒绝普通资料保存；推进对应阶段时，未完成名单核对先要求核对，已确认数量不足时要求人工处理或说明后继续。继续办理确认绑定阶段、名单版本和数量规则版本；名单或规则变化后原确认失效，需重新确认，原审计记录保留。

人工确认同时覆盖单阶段完成、批量完成/推进、API 调用；后台到时自动完成遇到待确认事项须保留待办并提示人工处理，不能绕过。旧版已自动流标或已完成项目不追溯恢复、更名或改写。

## 流程关联与项目调整

- 每种方式可使用通用模板，或独立编辑、复制现有方式的模板。阶段支持名称、顺序、图标、检查清单、业务模块及已有自动完成配置；校验唯一模块和依赖，保留现有保护。
- 新建项目选择方式后显示将采用的流程；创建事务内保存方式、制度、数量规则和阶段快照。创建与模板保存并发时采用一份完整版本，不能拼接新旧配置。
- 改名、排序、停用、调整默认规则或全局模板均不调用旧“同步现有项目”路径。
- 项目内提供“调整本项目流程”，复用阶段编辑能力；保存前显示新增、调整、移除影响，仅修改这个项目。
- 已完成阶段不删除、改名或改写完成记录；未完成且没有业务资料或依赖的阶段允许移除；有资料或期限/保证金/检查清单/提醒依赖的阶段禁止直接移除，并列明原因。
- 已有项目改选采购方式时，默认保留原阶段和业务记录；需明确选择并预览才调整尚未完成部分。项目方式和数量快照的变化留审计记录，不凭改选静默重排流程。
- 检查清单、报名、开标、评审、结果公告、通知书、保证金、期限助手、日历、批量推进和邮件均按项目阶段标识/模块解析，不按中文阶段名称推断。

期限助手可预填新项目明确选择的制度，但不自动启用、确认或重算法定期限。政府采购与招标制度分别对应原有类别；企业对应企业类别，集体与其他使用自定义类别且保留五类业务标签。已有项目的独立期限配置始终优先，不覆盖。

## 入口联动与旧数据往返

适配设置、新建弹窗、项目编辑/信息页、采购包规则与重新采购、侧栏筛选、总览/采购方式看板、批量推进、日历、邮件订阅/预览、项目导入导出、备份恢复。

- 导入模板提供制度和采购方式，并使用当前启用目录生成选项；支持旧模板唯一匹配的方式名称。
- 同名跨制度且缺少制度时逐行报错，要求补充，不随意选第一项；停用或未知方式不能用于创建新项目，不在导入时偷偷新增方式。
- 导出保留项目名称快照、制度及稳定标识；导出旧项目不因其方式停用而丢失记录。新字段兼容旧表头，不能改变其他资料列的含义。
- 名称、备注、例外说明和模板文字按文本处理及转义；Excel 导出继续执行公式注入防护；接口、重排数组、模板、数量等均服务端校验。

## 必须通过的验收

1. 管理：五类制度下新增、同名区分、编辑、改名、启停、排序、删除、引用保护、权限、失效版本及保存失败回滚。
2. 持久化：实际成品创建配置与项目，关闭隔离实例并重启核对；重复迁移、备份恢复后目录/引用/模板/例外/审计完整。
3. 历史：升级前后原阶段、完成记录、中标、报名、附件、保证金与期限设置逐项比对；全局改动和停用不会改写；原已流标保持原结果。
4. 数量：固定、不固定、包覆盖、例外说明；报名/接收/有效数量不混用；不足仅警告，继续办理留痕；名单/规则改变后确认失效；截止后不自动流标。
5. 防绕过：手动、批量、到时自动完成、直接 API、导入；并发创建/删除与保存冲突；不合法请求不部分落库。
6. 流程：独立/通用模板、自定义阶段/模块、复制、项目内调整、完成阶段与依赖保护；修改模板后新旧项目各用各自快照；竞价改名不丢模块。
7. 联动：按上述全部入口走一次，包含日历打开阶段、保证金起算、期限助手引用、邮件预览。只用隔离邮箱桩，不发真实邮件。
8. UI：四主题、1366/1920桌面、平板与390宽度，长中文名称、列表空态、错误态、键盘、焦点、滚动、图标；实测请求数和响应耗时，页面不为每个方式重复请求所有项目。
9. 构建：前后端现有回归、增加的业务回归与真实打包 EXE 端到端通过；跳过项和原生桌面人工未验项如实记录。
