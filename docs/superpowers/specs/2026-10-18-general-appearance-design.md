# 常规与外观优化补充设计

日期：2026-10-18。基础：v5.8.36现有系统、已确认的采购方式管理设计及本次原型评估。状态：用户已确认合并构建，按一期范围实施；二期内容不纳入本轮。

## 目标

将用户每天使用的界面偏好整合为一致、可保存、可恢复的设置。保留四主题、业务密度、自绘图标和既有功能；所有新增选项必须在相应界面真实生效，不保留只改变选中状态的演示控件。

## 一期拟合并开发的范围

### 1. 常规与外观

保持现有设置分类，页面包含四组内容：

- **主题与显示：** 四种现有主题缩略预览＋跟随系统；紧凑显示、内置预览、字号小/标准/大、动画正常/减少/关闭。
- **默认工作方式：** 默认首页、项目排序、侧栏显示字段。
- **日期与日历：** 日期显示格式、每周起始日、节假日/调休显示开关。
- **登录页显示：** 仅管理员可见，保留副标题显式保存及现有服务端校验。

页面上分别标注“仅当前账户和设备”和“系统配置，所有用户可见”。个人偏好即时生效并保存；管理员输入保持草稿，点击保存后成功才更新已保存值；切换主题、字号或其他选项不能重填或丢失其草稿。

### 2. 主题、字号与动画

“跟随系统”作为主题选择模式，使用当前系统浅/暗偏好映射到现有默认浅色/暗色；手动选择蓝/绿等固定主题时不受系统切换影响。首次升级保留原主题，不强制改成跟随系统。

字号通过共享令牌及组件适配覆盖侧栏、看板、阶段弹窗、设置、日历和表格；不只改变body。桌面维持业务密度，辅助文字尽量不低于12px；移动表单输入保持足够字号和触控范围。字号/紧凑模式组合下检查中文按钮不竖排、表格不遮挡、日期图标不移位。

动画的有效强度取用户设置与系统减少动态效果限制中更少动态的一项。减少模式取消大位移、视差和装饰性循环；关闭模式取消非必要过渡、平滑滚动和入场动画，但保留静态加载与操作反馈。复用命令中心等既有清理生命周期，不能因重渲染叠加监听器。

主题预览不访问远端图片或字体，不添加背景图、玻璃特效及持续动画。预览仅更新必要的CSS变量和组件状态，避免设置页整页重绘。

### 3. 默认首页、排序与字段

一期默认首页限定总览看板、日历视图、采购方式看板；保持当前默认总览。首次启动按偏好直接加载目标，不先完整加载总览再跳转。失效或无权限的目标回退总览并给出说明；不把设置页或某个项目设成无法返回的启动入口。

项目排序与现有侧栏编号升降序整合为一处偏好。新增进度、最近待办计划；标签明确，不用含糊的“截止时间”。缺少排序值排最后，相同值使用编号及稳定id排序，不更改数据库和业务阶段顺序。最近修改、创建时间和按开标时间排序待确认服务端可靠字段及阶段语义后再开放，不用最后一个完成日期冒充修改时间。

侧栏保留项目名称和状态；编号、采购方式、下一节点计划、进度为可选显示字段，提供标准/精简/完整预设。作用范围明确为侧栏，不隐式更改导出、业务表格、邮件内容。字段自由拖动和独立项目表格页放二期；以后如增加重排须提供键盘上下移动替代。

采购方式字段读取目录稳定标识及项目名称快照：同名不同制度可区分，停用方式的历史项目仍正常显示。更换显示偏好不能影响采购方式筛选或数量规则。

### 4. 日期与日历

显示格式支持 `YYYY-MM-DD`、`YYYY年M月D日`、`YYYY/MM/DD`，保留原格式作为升级默认。已有时分继续显示，不改变完成时间、计划时间、API值、数据库、导入导出、日期选择器原始值或邮件业务日期。

统一显示辅助函数复用既有日期/时区解析，不把纯日期重新转为UTC；空值、仅日期与含时分分别显示。表单内部仍用原ISO格式，不能把中文显示字符串回传当作保存值。

每周起始日仅允许星期日/星期一。保留现有默认；从同月完整的日期/事件数据重建星期标题、前后空格及网格，按原日期标识绑定事件。不只交换星期文字，也不简单旋转已有格子。原始月份数据缓存保留，派生布局缓存/渲染签名纳入周起始偏好，防止旧网格覆盖新选择。

节假日开关只控制日历底色、休/班标记及说明的显示；关闭后保证金期限、公告/其他业务期限、工作日计数和邮件发送规则完全不变。年度安排维护继续使用已有模板下载、导入预览、影响核对与历史版本；不新增联网抓取或第二份日历数据。

### 5. 文件与数据

把默认导出年份移到“文件与数据 → 导出偏好”，保留原值，不改变当次导出范围优先级。导出保存目录及管理员权限仍沿用现有逻辑；浏览器下载位置与桌面客户端保存目录分别说明。

一期核对所有导出入口中文文件名、标准响应头、非法字符处理及同名文件不覆盖，沿用现有可读命名，不增加“命名规则”下拉框。批量清单使用“项目列表＋年份＋日期”，单项目资料才使用真实的项目编号/名称及资料类型；下载模板保留类型与年度，不套成某个项目名称。

二期再提供固定、可预览的命名预设，并同时适配浏览器下载和客户端保存；不能出现前端偏好已保存但服务端下载名称完全未变的状态。不开放任意表达式、路径或脚本。

## 保存、迁移与恢复

一期个人偏好采用带版本号的本地配置，按当前访问来源、账户标识隔离；页面明确“仅当前账户和设备”，不声称跨设备同步。登录前主题只使用设备级主题选择，不读取其他账户的首页或项目偏好。服务端登录副标题等系统设置继续走已有权限和显式保存接口。

迁移读取现有 `pm_theme`、`pm_compact_mode`、`pm_preview_in_app`、`pm_default_export_year` 与 `projectSidebarSortDirection`。旧本地设置原来按设备共享，须以一次性、可追溯迁移处理，不能每次登录都复制给另一账户。迁移失败保留原值，不清空原存储；未知枚举使用安全默认并记录修复提示。

本地存储不可用或容量不足时，本次会话仍可使用，但界面提示“本次会话有效，未能保存”，不显示“已保存”。重启保持指同一客户端/浏览器配置、访问来源及账户；更换电脑、清理浏览器数据或更换访问地址不承诺自动同步。现有桌面入口已设置 `private_mode=False`，仍须在成品上验证实际持久化。

“恢复界面默认”先列出将恢复的个人偏好范围，再确认；不调用localStorage.clear，不重置登录副标题、导出目录、导出年份、邮箱、账号、授权、密钥、年度节假日数据、采购方式或流程模板。导出偏好如需重置，在其独立区域处理。恢复后原项目页面仍可继续操作。

## 二期再考虑

跨设备账户同步及冲突处理、完整项目列表页与任意字段重排、需要新增可靠服务端时间字段的排序、固定文件命名预设及受控占位符。它们有独立的接口、权限或数据含义，不作为原型中的一个下拉框直接纳入一期。

## 与采购方式管理合并的顺序

1. 先按原方案完成采购目录、稳定标识、项目快照和数量规则；其核心验收不因外观设置扩大而减少。
2. 加入统一个人偏好服务、设置归位和显示控件，复用原阶段编辑与设置草稿保护，不在两套分支各造一份设置存储。
3. 按目录/项目快照适配侧栏、采购方式看板和默认视图，统一日期显示及日历排布。
4. 合并做界面、性能、权限、历史保护和打包成品验收；完成本地交付后才处理公开发布。不提前切换现有运行程序，也不改正式版本号。

这是一份补充范围设计，不替代原七项实施计划；确认纳入的功能后才增补对应开发任务和用例。

## 验收清单

- 四主题及跟随系统：系统切换实时生效，固定主题不被覆盖，启动无明显主题闪烁。
- 字号×紧凑模式×四主题：侧栏、阶段面板、日期弹窗、表格、日历和设置均生效，图标不移位；1366/1920/768/390宽度无内容丢失。
- 个人设置不改管理员草稿；副标题保存失败保留输入；切换分类遵守既有未保存保护。
- 同设备不同账户不互相修改偏好；刷新、浏览器/隔离客户端重启后保持；禁用/损坏存储能降级且如实反馈。
- 默认首页只请求目标视图必要数据，不先完整请求总览再跳转；换排序/字段不逐项目请求详情或改变业务数据。
- 日期格式更换前后保存的原始日期时间逐项相同；星期一/星期日开头、跨月跨年、闰年二月、月末42格等布局均按日期标识核对，事件不丢失不移日。
- 关闭节假日显示前后，同一输入的保证金、业务期限与邮件工作日判定完全一致。
- 动画关闭时无非必要过渡/入场动画；系统减少动态效果始终受尊重，加载和错误状态仍清楚可见。
- 恢复界面默认只修改指定个人键；历史项目、采购目录、规则、邮件、许可证和附件哈希不变。
- 导出年份迁移、中文下载名、桌面指定目录、浏览器下载分支与重复导出逐项核对；不以原型交互替代实际成品验证。

本轮仅完成原型实测与补充设计，尚未执行这些正式功能验收。使用现有 UI UX Pro Max 与 Taste Redesign 的本地参考版本，保留产品约束，不引入新的UI框架。
